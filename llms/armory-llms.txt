# Armory

> Armory, Inc. built and sold an enterprise distribution of the open source Spinnaker continuous
> delivery platform - Armory Continuous Deployment (self-hosted and managed), Armory Continuous
> Deployment-as-a-Service, and a set of proprietary Spinnaker plugins including the Armory Scale
> Agent for Kubernetes, Pipelines-as-Code (Dinghy), an OPA-backed Policy Engine, Terraform
> Integration, GitHub Integration and AWS Event Cache. Harness acquired Armory's assets in January
> 2024. www.armory.io now redirects to harness.io, but docs.armory.io remains live, Armory CD is
> still shipping releases (v2.40.2 on 2026-07-27), and a real Swagger 2.0 API reference for the
> Scale Agent is still published.

Generated by API Evangelist on 2026-08-06 from the public Armory surface. Armory publishes no
llms.txt of its own - https://docs.armory.io/llms.txt returns 404.

## APIs

- [Armory Scale Agent API](https://docs.armory.io/plugins/scale-agent/reference/): the REST surface
  Clouddriver exposes when the Armory Scale Agent plugin is installed - Dynamic Accounts plus the
  Clouddriver application, cluster, server group, instance, job, credential, operation, task and
  infrastructure endpoints. 51 paths, 56 operations. Self-hosted; the endpoints are served by the
  operator's own Clouddriver at https://<clouddriver-loadbalancer-url>:<clouddriver-port>.
- [Armory Continuous Deployment API (Spinnaker Gate)](https://docs.armory.io/continuous-deployment/armory-admin/api-endpoint/):
  the Spinnaker Gate API. Armory documents exposing it for automation clients on a second port
  (8085) behind x509 client certificates, with the browser endpoint on 8084 using the cluster's
  primary identity provider.

## Notes for agents

- Idempotency: the `/ops` submission endpoints accept a `clientRequestId` query parameter that keys
  the resulting Task. Reuse it across retries of the same intent. `Task.requestId` echoes it back.
- `POST /ops` and `POST /ops/{name}` are deprecated in the published spec; use
  `POST /{cloudProvider}/ops` and `POST /{cloudProvider}/ops/{name}`.
- All writes are asynchronous: submit, take `StartOperationResult.id`, poll `GET /task/{id}`.
- The published spec declares no securitySchemes, no error schemas and no 5xx responses. It also
  carries two dangling `$ref`s (`#/definitions/Map` and `#/definitions/Set`) that never resolve.
- No MCP server, no GraphQL endpoint, no AsyncAPI document, no agent card, no /.well-known/ surface,
  and no status page exist on any Armory host.
